# 《高能宇宙大爆炸》数值与机制总策划案

> 版本：1.2  
> 日期：2026-07-15  
> 最后更新：2026-07-16  
> 状态：可交接实施  
> 适用范围：正式航程优先；Boss 挑战作为标准化测试/沙盒模式  
> 体验关键词：求胡、休闲、机制叠加起飞  
> 参考方向：《杀戮尖塔》但更轻松；《以撒的结合》的规则交互与胡局破坏感

## 1. 设计结论

本项目不追求所有构筑等强，也不以攻击、生命、敌人血量的规则增长作为主要乐趣。标准构筑应稳定具备通关能力，强构筑显著加快战斗，胡局则被允许突破通常的战斗节奏。

核心承诺：

1. 新玩家能理解基础规则，不需要先学习复杂公式。
2. 单件装备提供明确机制，组合后产生新的行为，不只是更大的面板数字。
3. 玩家在第一场 Boss 前开始形成方向，第二场 Boss 前完成核心循环，最终 Boss 前允许机制链起飞。
4. 白板与普通构筑按 1–3 分钟 Boss 战设计；真正胡局允许在 20–50 秒内击杀 Boss。
5. 局外成长只包括航前校准和进阶危机，不设置永久攻击、生命、掉率等纵向属性树。

### 1.1 非目标

- 不追求竞技级精确平衡。
- 不要求每件装备在任何构筑中都有相同收益。
- 不通过无止境提高敌人伤害维持后期难度。
- 不以“敌人 HP 与玩家 DPS 同比例膨胀”作为唯一成长方式。
- 不制作可无限触发、无法追踪来源的通用脚本系统。
- 不要求一次性重写现有 142 件装备；允许分批迁移和验证。

## 2. 成功指标

### 2.1 局时

| 玩家状态 | 完整局时目标 |
|---|---:|
| 快速决策/胡局 | 32–40 分钟 |
| 普通成功局 P50 | 45–52 分钟 |
| 谨慎搜刮局 P90 | 55–60 分钟 |

### 2.2 通关率

标准难度只做一档，目标条件胜率如下：

| 战斗 | 新玩家 | 熟练玩家 |
|---|---:|---:|
| 第一 Boss | 85% | 98% |
| 第二 Boss | 75% | 97% |
| 最终 Boss | 60% | 96% |

计入探索房阵亡后，完整通关率目标为新玩家约 30%、熟练玩家约 90%。

### 2.3 战斗时间

所有时间均使用“当前阶段正常构筑”测量，不使用开局白板测量终局敌人。

| 对象 | 目标击杀时间 |
|---|---:|
| 普通怪 | 2–5 秒 |
| 危险普通怪 | 5–8 秒 |
| 精英 | 45–75 秒 |
| 第一 Boss | 60–100 秒 |
| 第二 Boss | 75–130 秒 |
| 最终 Boss | 90–160 秒 |
| 胡局 Boss | 20–50 秒，允许更快的极端个案 |

## 3. 正式航程结构

### 3.1 保留的现有锚点

- 危机阈值保留为 5 / 12 / 21。
- 每完成一个结算节点，危机 +1、算力容量 +1。
- 初始算力容量保持 5。
- 三个 Boss 前累计装配辅助机目标为 3 / 5 / 8 件。
- 对应可用算力约为 10 / 17 / 26，恰好支撑平均每件约 3 点算力的构筑。

### 3.2 节点组成

21 个结算节点的典型实际选择目标：

| 节点类型 | 一局完成数量 |
|---|---:|
| 探索战斗 | 8–9 |
| 事件 | 6–7 |
| 奖励/信标/其他非战斗 | 5–7 |

世界地图可以继续提供 45–55 个候选节点，但生成与可达路径应使玩家实际选择接近上述比例。推荐把战斗/事件/奖励的基础生成权重从当前约 5:2:1 调整到约 3:3:2，特殊信标在此之外单独生成。

### 3.3 单节点时间预算

| 内容 | 目标时间 |
|---|---:|
| 70% 搜刮探索房 | 3–5 分钟 |
| 后期胡局探索房 | 1.5–3 分钟 |
| 普通事件/奖励选择 | 20–45 秒 |
| 商店/机库整理 | 每次 30–90 秒 |

## 4. 玩家基础生存预算

### 4.1 生命与伤害

玩家最大生命保持 100。

| 伤害类别 | 无减伤结算值 | 设计用途 |
|---|---:|---|
| 轻微擦伤/DoT | 1–3/秒 | 迫使移动，不应单独致死 |
| 普通攻击 | 5 | 满血约承受 20 次 |
| 危险普通攻击 | 8–12 | 明显惩罚连续失误 |
| 重击 | 34–40 | 三次致死，必须有清楚预警 |

规则：

- 重击不能在一次操作失误中重复多段结算。
- 同源持续伤害每秒结算，不绕过统一减伤规则。
- 普通受击无敌帧维持约 1 秒；重击可使用 0.7–1.0 秒，但不能依靠多段碰撞秒杀。
- 后期难度主要增加攻击组合、空间压力与决策成本，不显著提高单次重击伤害。

### 4.2 恢复预算

- 第一阶段总可见治疗：约 25–40 HP。
- 第二阶段新增治疗：约 35–55 HP。
- 第三阶段新增治疗：约 45–70 HP。
- 正常玩家进入 Boss 时目标生命中位数为 70–90。
- 治疗用于消除探索中的小额损耗，不应抵消三次连续重击。

## 5. 玩家火力与成长倍率

### 5.1 归一化基准

以开局脉冲机炮为 1.0 倍。当前白板攻击 10、射击间隔 0.25 秒，理论单体持续 DPS 约为 40，后续测试使用标准靶场实测值作为 `D0`。

| 阶段 | 正常构筑 | 成型构筑 | 胡局 |
|---|---:|---:|---:|
| 第一 Boss 前 | 2.0–2.5× | 3.5× | 5× |
| 第二 Boss 前 | 4–5× | 7–9× | 12–16× |
| 最终 Boss 前 | 8–10× | 14–18× | 25–35× |

倍率指综合清场效率，包括范围、追踪、连锁、僚机和触发频率，不等于面板攻击力。

### 5.2 成长来源约束

- 纯攻击、射速、弹量等基础数值合计原则上不超过白板的 2 倍。
- 终局普通构筑剩余 4–5 倍效率来自机制组合。
- 胡局额外倍率来自转化器、跨家族桥接与触发链。
- 稀有度提高主要增加规则复杂度和组合能力，不只是增加数值百分比。

### 5.3 阶段实测 DPS 建议值

以下数值用于第一轮 Boss/精英 EHP 反推，必须通过标准靶场校准：

| 阶段 | 正常构筑实测有效 DPS | 胡局有效 DPS |
|---|---:|---:|
| 第一 Boss 前 | 70–85 | 170–220 |
| 第二 Boss 前 | 145–175 | 450–600 |
| 最终 Boss 前 | 300–380 | 1000–1400 |

## 6. 敌人与 Boss 预算

### 6.1 普通怪

普通怪使用“基础 HP × 阶段系数 × 行为系数”。

- 基础 HP：240。以阶段有效 DPS 中位数 78/160/340 计算，标准行为怪 TTK 约为 3.1/3.2/3.0 秒。
- 阶段系数：1.0 / 2.1 / 4.3。
- 行为系数：脆弱 0.8、标准 1.0、耐久 1.35、危险核心 1.7。
- 每个怪的阶段 TTK 应保持在 2–5 秒，危险怪 5–8 秒。

伤害不随 HP 同比例增长：

- 标准弹/碰撞以 5 点为中心。
- 高威胁普通怪以 8–12 点为中心。
- 只有狙击、重型冲锋、明显蓄力攻击使用 34–40 点重击。

### 6.2 精英

精英不是放大的普通怪，必须至少有一个改变战场规则的机制。

| 阶段 | 目标有效生命 EHP |
|---|---:|
| 第一阶段 | 4,800 |
| 第二阶段 | 9,600 |
| 第三阶段 | 20,400 |

规则：

- 精英伤害窗口、护盾、瞬移等机制全部折算进 EHP。
- 一个普通探索房默认不同时安排两个 1 分钟精英。
- 约 20%–30% 的战斗房包含精英；一局目标 2–4 场完整精英战。
- 精英提供明确额外收益，不从无限巡逻波中重复刷取。

### 6.3 Boss

Boss 先按目标时间反推有效生命：

`目标 EHP = 阶段有效 DPS × (目标总时长 - 强制演出/不可攻击时间)`

第一轮建议：

| 阶段 | 基准 EHP | 建议强制演出/不可攻击时间 |
|---|---:|---:|
| 第一 Boss | 5,600 | 10–15 秒 |
| 第二 Boss | 14,500 | 15–25 秒 |
| 最终 Boss | 36,000 | 20–30 秒 |

- 各家族可在基准 EHP 上浮动 ±15%。
- 护盾、闭眼无敌、炮台分体、减伤阶段必须计入 EHP，不能在此基础上再次无预算叠加。
- Boss 难度随阶段增加技能组合和并发压力，技能伤害仍遵守普通攻击/重击预算。
- 胡局击杀时间低于一分钟属于奖励，不应自动给 Boss 添加动态减伤。

## 7. 冲刺重构

### 7.1 默认定位

默认冲刺是躲避 Boss 特定技能和快速改位，不是全流派主输出。

建议基础值：

- 2 次充能。
- 每次充能恢复 1.8 秒。
- 距离 420、速度 2400，持续约 0.18 秒。
- 无敌覆盖冲刺持续时间，额外尾帧不超过 0.05 秒。
- 基础撞击伤害为 0.5–1.0 倍攻击力。
- 默认撞到障碍停止；反弹、连锁和余震由星间巨构装备解锁。

### 7.2 星间巨构转化

星间巨构流派按以下路径成长：

`冲刺命中 → 撞击倍率 → 折返蓄能 → 余震 → 余震触发其他机制`

建议阶段能力：

- 2 件：冲刺伤害达到常规主炮的可比水平，解锁一次反弹。
- 4 件：余震成为主要清场来源，命中精英/Boss 可返还部分充能。
- 胡局：余震可触发弹幕、标记或僚机协同，但遵守触发世代限制。

## 8. 狂热重构

### 8.1 覆盖率

- 热量上限 100。
- 标准构筑平均约 10 秒充能、5 秒爆发，覆盖率约 33%。
- 非地狱之眼构筑目标范围 25%–40%。
- 地狱之眼成型构筑目标范围 50%–70%。
- 极端胡局可以接近常驻，但需要多件明确联动装备。

### 8.2 热量获取

不再直接把实际伤害等额转换为热量，否则后期 DPS 会自动制造满覆盖率。

建议：

- 主体直接命中：2.5 热量。
- 次级/生成弹命中：1.0 × 触发系数。
- 击杀普通怪：3 热量。
- 击杀精英：12 热量。
- 玩家受伤：`min(伤害 × 0.5, 8)`。
- 非地狱之眼基础热量获取上限：12/秒。
- 地狱之眼装备可以把上限提高到 18/24，并增加获取倍率。
- 狂热期间默认不获取热量。

### 8.3 狂热基础效果

- 射击间隔 ×0.60–0.65。
- 承受伤害 ×0.60。
- 不默认提供巨额独立伤害乘区；伤害转化留给地狱之眼装备。

## 9. 机制叠加系统

### 9.1 方案比较

#### 方案 A：继续硬编码每件装备

优点：单件实现快。  
缺点：142 件装备会形成大量分支，联动难追踪，后续平衡成本最高。

#### 方案 B：有限触发器 + 数据定义（推荐）

装备引用受控的触发、条件和动作枚举；运行时由统一机制节点处理。复杂装备仍可挂专用处理器。

优点：可验证、可追踪、能批量制作联动。  
缺点：需要先建立事件协议和迁移基础样例。

#### 方案 C：完全通用的效果图脚本

优点：理论自由度最高。  
缺点：极易产生递归、性能和存档兼容问题，不适合当前项目阶段。

采用方案 B。

### 9.2 机制定义

每个效果包含：

- `effect_id`
- `trigger`：射击、命中、击杀、冲刺命中、狂热开始、僚机行动、拾取矿物等。
- `required_tags`
- `blocked_tags`
- `action`
- `magnitude`
- `internal_cooldown`
- `stack_rule`：相加、相乘、取最大、唯一。
- `inherit_mask`：生成物继承哪些能力。
- `proc_coefficient`：次级触发效率。

运行时事件至少包含：

- 来源实体与装备 ID。
- 目标实体。
- 机制标签。
- 触发世代 `generation`。
- 事件谱系 ID `lineage_id`。
- 当前触发系数。

### 9.3 防无限递归规则

- 最大触发世代为 3。
- 同一个 `effect_id` 不能在同一事件谱系内再次触发自己。
- 次级伤害/触发系数建议按世代乘 1.0 / 0.65 / 0.35 / 0.15。
- 每秒新增玩家弹体设置性能预算；建议初始软预算 180、硬上限 260。
- 超出软预算后合并纯视觉弹体或降低次级生成数量，不能静默删除主体攻击。
- 所有触发在调试模式下可输出来源链。

### 9.4 装备角色

装备按机制角色分类，而不是只按稀有度分类：

- 启动器：解锁新行为。
- 放大器：强化已存在的行为。
- 转化器：把一种事件转为另一种事件。
- 桥接器：允许两个家族机制交互。
- 稳定器：防御、经济、容错。

商店与掉落需要识别角色，防止只给放大器却不给启动器。

### 9.5 五家族机制主轴

| 家族 | 主循环 | 胡局方向 |
|---|---|---|
| 星间巨构 | 冲刺命中 → 折返 → 余震 | 余震触发弹幕、标记或僚机协同 |
| 天堂号 | 多弹道 → 分裂/穿透 → 连续覆盖 | 生成弹继承部分主体机制并形成光雨 |
| 扭曲星核 | 追踪/标记 → 聚怪 → 引力井 | 死亡引力井重新聚怪并转移弹道 |
| 地狱之眼 | 热量 → 狂热 → 创伤/红线 | 狂热重置触发冷却、扩大其他机制频率 |
| 神明使者 | 僚机槽位 → 职能协作 → 同步触发 | 僚机以低系数复制玩家的核心触发 |
| 通用 | 生存、回收、信息、桥接 | 补齐启动器或降低构筑断档 |

推荐跨家族桥接示例：

- 天堂分裂弹继承扭曲追踪，但只继承 35%–65% 强度。
- 巨构余震可以施加质量标记，引力井因此在冲刺落点生成。
- 神使僚机命中可以积累少量狂热，但受每秒热量上限控制。
- 狂热开始可重置一个僚机或冲刺机制冷却，不能重置所有冷却。

## 10. 探索房机制与收益

### 10.1 搜刮进度

新增“回收价值进度”，按价值而不是按物件数量计算：

- 普通矿脉：1 点。
- 宝箱：3 点。
- 精英守卫缓存：5 点。
- 特殊目标：按房间配置 3–8 点。

流程：

1. 生成房间后计算总回收价值。
2. 达到 50% 时显露撤离方向与剩余高价值目标。
3. 达到 65% 时激活撤离点。
4. 因最近目标和撤离路线影响，实际玩家搜刮中位数应落在 70%–80%。

收益分布：

- 前 70% 内容提供约 80%–85% 的稳定收益。
- 剩余内容提供 15%–20% 稳定收益，并提高装备、富矿、特殊事件概率。
- 不强制清敌；敌人承担停留税、路线封锁和风险升级。

### 10.2 敌压

| 阶段 | 基础巡逻间隔 | 常态同时敌人数上限 |
|---|---:|---:|
| 第一阶段 | 35 秒 | 8 |
| 第二阶段 | 30 秒 | 10 |
| 第三阶段 | 25 秒 | 12 |

战斗档案在此基础上最多浮动约 ±25%。无限生成巡逻敌人的收益应递减或不提供装备掉落，避免安全刷取。

## 11. 经济与装备获取

### 11.1 阶段目标

以下辅助机数量均不包含主武器：

| 时点 | 已拥有 | 已装配 | 已用算力 | 累计矿物收入目标 |
|---|---:|---:|---:|---:|
| 第一 Boss 前 | 4–6 | 3 | 8–10/10 | 180–240 |
| 第二 Boss 前 | 8–11 | 5 | 15–17/17 | 500–650 |
| 最终 Boss 前 | 14–18 | 8 | 23–26/26 | 1100–1400 |

### 11.2 单房收入

以 70% 搜刮为准：

| 阶段 | 探索房矿物收入 |
|---|---:|
| 第一阶段 | 55–75 |
| 第二阶段 | 85–115 |
| 第三阶段 | 125–170 |

事件按阶段提供约 30–135 的等价价值，奖励节点提供约 55–175；装备选择按其商店价和定向质量折算，详细预算见第 20.2 节。

### 11.3 装备价格

现有价格区间可基本保留，按机制强度复核：

- 普通：50–90。
- 稀有：100–155。
- 史诗：170–220。
- Boss：不可购买。

标准状态下，一次进入商店通常买得起 1 件关键装备；经济胡局可以买 2 件，但不能在一次普通探索后买空商店。

### 11.4 商店 12 格组成

- 5 格：按稀有度和阶段抽取的通用候选。
- 3 格：当前主家族候选。
- 2 格：根据现有启动器寻找缺失的放大器/桥接器。
- 1 格：生存或经济稳定器。
- 1 格：通配候选；危机 12 后可成为史诗保底位。

定向不是保证完整构筑，只是减少“有放大器但永远没有启动器”的死局。

### 11.5 重抽与掉落保护

建议付费重抽：

`价格 = 18 + 当前阶段 × 10 + 本局已付费重抽次数 × 14`

目标：普通局付费重抽 1–2 次，相关校准/契约构筑可达到 3–4 次。

装备保护：

- 连续 3 个结算节点没有获得任何新装备时，下一个奖励缓存必定出现装备选择。
- 第一 Boss 前若辅助机少于 3 件，节点 4 的商店或奖励必须提供至少一个可负担启动器。
- 不生成重复装备，除非未来明确设计“重复升级”系统。

## 12. 航前校准

### 12.1 原则

- 每局只能选择 1 项校准。
- 校准提供规则、信息或构筑方向，不形成永久数值等级。
- 解锁是横向的；已解锁校准不会升级为更大的百分比。
- 玩家失败后仍可能通过到达新里程碑解锁选项，因此失败不等于完全归零。

## 15. 数据与运行架构

### 15.1 数据所有权

- `RunManager`：只拥有当前一局的航图、经济、装备、危机和节点状态。
- `MetaProgressionManager`：只拥有已解锁校准、已解锁进阶危机、最高通关层和当前航前选择。
- `MechanicRuntime`：玩家实例拥有，保存本局已装配效果的运行时冷却和事件谱系。
- 配置 Resource：只读共享；运行时不得直接修改。
- 玩家/敌人/Boss：拥有各自瞬时生命、位置和技能状态。

### 15.2 推荐配置资源

不要创建一个巨型 `GameBalanceConfig`。拆分为：

- `RunPacingConfig`：节点比例、局时目标、房间压力。
- `CombatBalanceConfig`：伤害类别、阶段 HP/EHP、狂热和冲刺基础值。
- `EconomyBalanceConfig`：收入、价格、重抽和掉落保护。
- `CalibrationData`：单个航前校准定义。
- `AdvancedCrisisData`：单个进阶危机定义。
- `MechanicEffectData`：单个机制效果定义。
- `EventDefinition` / `EventOptionData`：事件主题、出现条件、选项、成本与结果定义。
- `RewardDefinition` / `RewardPoolData`：奖励卡、节点奖励池与保底标签。
- `BeaconData`：局内信标的规则键、运行时钩子、互斥组与航路回响定义。

现有 `EquipmentCatalog.gd` 第一阶段继续作为装备静态目录，只新增机制标签和效果 ID。机制稳定后再决定是否迁移为完整 Resource 集合。

### 15.3 持久化

玩家可写数据使用 `user://meta_progression.json`，不用 `.tres/.res`：

```json
{
  "version": 1,
  "unlocked_calibration_ids": ["wide_scan", "procurement_voucher", "resonance_compass"],
  "selected_calibration_id": "wide_scan",
  "highest_unlocked_crisis": 0,
  "highest_cleared_crisis": -1,
  "selected_crisis": 0,
  "milestones": {}
}
```

必须提供版本迁移、写入失败处理和损坏存档回退。局内存档继续由 `RunManager` 管理，两种存档不可互相覆盖。

### 15.4 单一数值主表与 Resource 生成

所有首轮实际数值统一维护在 `data/balance/master_balance.tsv`。选择 TSV 是为了避免 Godot 将普通 `.csv` 自动误识别为多语言翻译表。它是策划编辑源，不是运行时直接读取文件：

1. 每行由 `domain + id` 唯一标识，不能重复。
2. 普通标量使用 `value`；阶段值使用 `stage_1/stage_2/stage_3`。
3. `data_type` 决定严格解析类型；单位由 `unit` 显式声明。
4. 主表固定为 14 列；复合内容统一写入 `attributes`，其中 `payload=` 之后为受控效果字段。字段以分号分隔，阶段数组使用 `第一/第二/第三阶段`顺序的 `/`，候选集合使用 `|`。
5. 导入器按 `domain/kind` 生成多个小型只读 `.tres`，不得生成一个巨型 Resource。
6. 游戏只加载生成后的 typed Resource；不得在运行时反复解析 CSV。
7. 生成文件带主表内容版本和校验摘要。手工修改生成的 `.tres` 必须被检查判定为漂移。

主表当前共 373 条数据记录，包含系统节奏、玩家、普通怪、精英、Boss、冲刺、狂热、机制上限、探索、经济、装备预算、20 件主武器、122 件辅助机、奖励、24 项事件、26 个信标、8 项校准和 10 层进阶危机。WG-06 复核装备角色与机制后仍只修改这张主表，不另建第二份权威数值表；并行开发阶段通过集成请求交由主表所有者合入。

## 18. 验收标准

第一轮数值与机制改造完成需满足：

1. 100 次自动生成航图中，可达选择的预期战斗房数量中位数为 8–9。
2. 无校准、危机 0 的标准模拟中，Boss 前装配中位数为 3/5/8。
3. 70% 搜刮房间的矿物收入落在阶段预算内。
4. 白板冲刺不能成为持续单体主输出；巨构 4 件构筑可以。
5. 标准构筑狂热覆盖率为 25%–40%，地狱之眼 4 件构筑为 50%–70%。
6. 普通/精英/Boss TTK 分别落入本案目标范围。
7. 胡局机制链可以显著突破普通时长，但事件世代不超过 3，弹体不突破硬上限。
8. 元进度存档损坏时安全回退，不影响局内存档。
9. 校准只选 1 项，进阶危机按最高已解锁层限制。
10. 所有新增数值均来自配置或集中常量，不散落在 UI 与特效脚本中。

## 19. 调整数值的顺序

严格按以下顺序调试，避免循环返工：

1. 白板移动、射击、冲刺、受伤。
2. 普通怪 2–5 秒 TTK 与 20 次普通攻击生存。
3. 单探索房 3–5 分钟与 70% 搜刮收益。
4. 第一阶段 3 件装配和第一 Boss。
5. 第二阶段 5 件装配和第二 Boss。
6. 第三阶段 8 件装配和最终 Boss。
7. 五家族标准构筑。
8. 跨家族桥接与胡局上限。
9. 航前校准。
10. 进阶危机。

不要先平衡 142 件单品，再回头修改基础规则。

## 20. 事件系统

### 20.1 事件的职责与交互规则

事件不是随机发钱按钮，而是让玩家用当前状态换取一次方向调整。它与另外两类节点的职责严格区分：

- 事件：即时取舍、短期契约、改道、构筑转换；通常不保证净赚。
- 奖励：稳定抬升本局强度并修复构筑断档；不制造隐性惩罚。
- 信标：不占算力，整局改变一条规则；主要代价是航路机会成本。

事件节点先抽取 1 个事件主题，再显示 2 个有效选项和“离开”。少数重大事件可以显示 3 个有效选项。所有代价必须在确认前完整展示，不使用隐藏永久负面结果。无法支付的选项置灰并说明原因，不能在点击后才失败。

预计单局实际遭遇 5–7 个事件，中位数为 6。前 4 个节点至少有 1 个安全事件进入候选池；同一 `event_id` 每局最多出现一次；同一家族路线事件连续不超过 2 次。

### 20.2 事件等价价值

仅用于内部平衡，不向玩家展示“等价矿物”公式：

| 内容 | 第一阶段 | 第二阶段 | 第三阶段 |
|---|---:|---:|---:|
| 安全事件净价值 | 30–45 | 45–65 | 65–90 |
| 风险事件成功净价值 | 45–65 | 70–95 | 100–135 |
| 奖励节点净价值 | 55–80 | 85–120 | 125–175 |
| 1 点永久算力等价价值 | 45 | 70 | 95 |

治疗按“实际恢复量”计价，溢出治疗只按 50% 折成星髓矿。高风险事件的期望净值约为同阶段安全事件的 1.25–1.45 倍；赌博事件即使失败也必须保留至少 40% 的安全事件价值，避免休闲局被一次坏骰完全摧毁。

### 20.4 事件数据与结算

`EventDefinition` 至少包含：`event_id`、阶段范围、权重、主题标签、唯一性、前置条件、`options`。`EventOptionData` 包含：成本列表、效果列表、持续节点数、预览文本和 AI/模拟标签。

Resolver 只接受白名单动作，例如 `grant_minerals`、`heal`、`grant_compute`、`draft_equipment`、`add_contract`、`mutate_unvisited_node`、`add_pity_tag`。事件脚本不得直接写 `RunManager` 字段。一次选择先生成 `RunMutationSet`，验证费用和状态版本后由 `RunManager` 统一提交，避免扣了资源却没有发奖的半结算状态。

## 21. 奖励节点与 Boss 奖励

### 21.1 奖励节点规则

奖励节点不进入 3–5 分钟探索房，目标交互时间为 20–40 秒。节点展示 3 张奖励卡且只能选 1 张：

- 同一组中最多 1 张纯矿物卡。
- 当装配低于阶段目标或触发装备保底时，至少 1 张是可立即使用的构筑卡。
- 奖励卡在点击前展示装备角色、家族标签、占用算力、与当前构筑的连接原因。
- 不能生成重复装备；无合法装备时自动转换为同价值机制卡或矿物，不给空奖励。

### 21.2 首发奖励池

| 奖励池 | 三选一候选规则 | 目标用途 |
|---|---|---|
| 稳定补给 | 45/70/105 矿物；修复 26/34/42；矿物与修复各半的混合包 | 为低血量或差经济提供确定性恢复 |
| 装备三选一 | 3 件非重复装备；至少 1 件符合当前家族，至少 1 件符合当前缺失角色 | 常规提升与求胡入口 |
| 机制启动器 | 3 件能独立触发机制循环的普通/稀有装备；第一 Boss 前只从可负担算力池抽取 | 修复“只有放大器、没有触发源” |
| 机制放大器 | 根据已拥有启动器生成 2 件匹配放大器 +1 件通用稳定器 | 推动标准构筑成型，不保证胡局 |
| 跨家族桥接 | 从当前两个最高标签家族生成 2 件桥接器 +1 件通用桥接器 | 允许规则叠加起飞；第一阶段默认不出现 |
| 修复/算力 | 修复 32/42/52；算力 +1；支付 24/36/52 矿物换算力 +2 | 处理生存和装配容量瓶颈；`+2` 每阶段最多出现一次 |
| 高风险富矿 | 立即获得 75/120/180 矿物并使下个战斗房必有精英；或获得 55/85/125 矿物无附加风险 | 给经济流一个可控的冒险按钮 |
| 家族档案 | 当前航路家族 3 选 1，候选角色必须互不相同 | 强化航路身份，不能三张都是同类纯伤害 |

现有 `ore_vault`、`sealed_armory`、`silent_cache`、`hazard_cache`、`ancient_foundry` 和五家族仓库名称继续作为节点外观与奖励池权重，不再各自硬编码一套结算逻辑。

### 21.3 掉落保护

奖励服务在准备候选时读取只读 `RewardContext`：已拥有/装配装备、算力、生命、距 Boss 节点数、连续无装备节点数和近 4 次候选角色。

1. 连续 3 个结算节点未获得新装备：下个奖励节点锁定 1 张装备三选一。
2. 第一 Boss 前装配少于 3：Boss 前最后一个奖励/商店强制出现可装配启动器。
3. 第二/最终 Boss 前低于 5/8：提高构筑卡而非白送装备，P25 仍允许落到 4/7。
4. 连续 4 次没有启动器：下一构筑卡必为启动器。
5. 已有启动器但连续 4 次没有匹配放大器：下一构筑卡必含 1 件放大器。
6. 保底只保证“有选择”，不自动装配、不免除算力和购买成本。

### 21.4 Boss 后奖励

每个 Boss 后固定显示 4 选 1：

- 1 件该 Boss 家族的 Boss 装备。
- 1 件匹配玩家当前主循环的非 Boss 稀有/史诗装备。
- 1 件跨家族桥接器；第一 Boss 后若尚无两个家族，则改为启动器。
- 1 个核心维护包：算力 +2，并修复 25/35/45 生命，不计入辅助机件数。

Boss 装备承担改变规则的职责，不允许只是普通装备的更高百分比版本。若玩家放弃装备选择核心维护包，后续 2 个奖励节点的装备权重提高，防止 3/5/8 节奏永久掉队。

## 22. 局内信标与航路回响

### 22.1 生成、选择与叠加

- 正式航程默认生成 2 个可达信标节点；事件最多额外接入 1 个远距信标，因此常规上限为 3 个。
- 每个信标节点显示 3 选 1：一个贴合当前主家族、一个跨家族/通用、一个经济或防御候选。
- 信标不占算力、整局有效，代价是选择该航路并放弃同层其他节点。
- 同一 `beacon_id` 不重复；相同 `rule_key` 的信标互斥，不做数值叠层。
- 激活后未来 3 个未生成/未进入节点获得“航路回响”：对应家族候选权重 ×2，并保证至少出现一次相关事件或奖励候选。回响只改变内容分布，不额外叠加伤害。

## 23. 事件、奖励、信标的服务边界

建议场景/对象关系：

```text
RunManager (本局权威状态与唯一提交者)
└── RunContentFacade
    ├── EventService -> EventResolver -> EventDefinition[]
    ├── RewardService -> RewardResolver -> RewardPoolData[]
    └── BeaconService -> BeaconResolver -> BeaconData[]

WorldMap UI -> 请求候选 -> RunManager 适配器 -> RunContentFacade
WorldMap UI <- ChoiceView[] / ResolveResult <- RunManager 统一提交 RunMutationSet
MechanicRuntime <- 已激活规则快照 <- RunManager
```

冻结的最小接口：

```gdscript
prepare_choices(node_id: int, context: RunContentContext, seed: int) -> Array[Dictionary]
resolve_choice(node_id: int, choice_id: String, context: RunContentContext, seed: int) -> RunMutationSet
validate_mutation(context: RunContentContext, mutation: RunMutationSet) -> PackedStringArray
commit_mutation(mutation: RunMutationSet) -> Dictionary
get_active_rule_snapshot() -> Dictionary
```

`ChoiceView` 只提供 UI 所需的 ID、标题、描述、预览、风险、禁用原因和标签；UI 不读取 Resource 内部字段。`RunContentContext` 是 `RunManager` 状态的只读快照。三个 Resolver 不持有 UI 引用、不直接存档、不直接修改玩家节点。

兼容期保留现有 `prepare_event_choices`、`resolve_event_choice`、`prepare_reward_event_choices`、`resolve_reward_event_choice` 等公开方法，由 `RunManager` 转发到新服务。待所有检查迁移后再删除旧 Dictionary 常量。

## 24. 新增内容验收指标

1. 1000 个固定种子中，单局可达事件中位数 6、奖励节点中位数 2、信标节点中位数 2。
2. 每个事件选择均可在确认前还原成本与结果；无支付能力时不产生半结算。
3. 危机 0 的事件选择率中，安全/风险/构筑/路线类没有任何一类长期低于 10%。
4. 奖励保底下，Boss 前装配中位数保持 3/5/8，且 P25 不低于 2/4/7。
5. 低于 30 生命时，奖励三选一至少有 1 个生存选项的概率不低于 70%，但不强制每次治疗。
6. 每个信标在遥测中能记录独立的规则触发次数；若只能记录“伤害 +X%”，判定设计未完成。
7. 同一来源递归世代不超过 3；信标胡局也不得突破弹体和每秒触发硬上限。
8. 事件/奖励/信标内容均能只通过新增 `.tres` 和白名单 Resolver 动作扩展，不需要再次编辑 `RunManager.gd`。
9. 存档记录内容 ID、剩余持续节点和必要参数；内容被删除时安全忽略并给出迁移日志。
10. 事件、奖励和信标共同提升构筑成型率，但危机 0 标准局仍有明显强弱局差异，胡局不被保底系统直接制造。
